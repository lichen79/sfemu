# Debugger Implementation Plan (sub-project E2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop the machine, look at the CPU and memory over the paused game, step one instruction, and set a breakpoint that stops it there again.

**Architecture:** An overlay drawn into the framebuffer, so the debugger is pixels and pixels are testable. A hand-written 4×6 bitmap font and four panels live in `crates/frontend`; `crates/machine` gains `step_instruction` (with `run_scanline` refactored to call it) and a side-effect-free `peek_word`; `crates/sfemu`'s loop consults the debugger and gains six keys. No new dependency in any crate.

**Tech Stack:** Rust 2021, rust-version 1.93. `m68k::disasm` reached through `machine`'s `pub use m68k` — already available, `std` is a default feature.

**Spec:** `docs/superpowers/specs/2026-08-08-debugger-design.md`

## Global Constraints

- **No ROM is bundled, fetched, downloaded, or committed by any code in this repository, for any purpose — including diagnostics and test fixtures.** Every automated test uses synthetic data the test itself writes. No URL to any ROM appears anywhere. The usage text must keep passing `!u.contains("http")`.
- **No new dependency in any crate.** Not in `frontend`, not in `machine`, not in `sfemu`. Verified before this plan was written: `machine` does `pub use m68k`, and `m68k`'s `std` feature (which gates `disasm`) is on by default. `frontend` must reach the core as `machine::m68k::...` and must **not** gain `m68k` in its manifest — that would let it reach past `machine`, which the re-export exists to prevent.
- **`minifb` appears in exactly one file: `crates/sfemu/src/display.rs`.** `the_windowing_library_is_named_in_one_file` enforces it and must stay green.
- **No logic behind the display boundary.** Every debugger decision — layout, formatting, which panel, what a key does — lives in `frontend`. `display.rs` gains only the new arms of the total `Key` match.
- **No clock access outside `display.rs`.**
- **The debugger's reads must not change what the machine does.** `peek_word` takes `&self`. Task 2's tests prove the machine is untouched; Task 7's proves a full run with the overlay on and off reaches identical state.
- **Expected values in tests are written as literals**, never derived by calling the code under test or its inverse. In particular: panel text is asserted by reading glyphs back **off the buffer**, not by comparing against the same `format!` the renderer used.
- **`#![forbid(unsafe_code)]` and `#![warn(missing_docs)]`** hold in `frontend`; every new public item is documented.
- **rustdoc cannot resolve `cfg(test)` items.** Refer to tests with plain code spans (`` `tests::foo` ``), never `[`tests::foo`]`.
- **The gate before every commit:** `cargo fmt --all` (first), then `cargo fmt --all --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --workspace`, `cargo test --workspace --release`. All clean. **Any task touching `machine` also re-runs `cargo run -q -p testrunner --release --bin report -- --test suite` and must report 127/127** — that is Tasks 1 and 2.
- **No test is `#[ignore]`d and no test reads an environment variable to decide whether to run.** The single existing exception is `crates/sfemu/tests/boot.rs`.
- **No test opens a window.**
- **Commit per task, not per session.** After compaction you cannot tell your own uncommitted work from a stranger's.

### Task 1: `step_instruction`, and `run_scanline` built on it

**Files:**
- Modify: `crates/machine/src/cps1.rs:101-150` (`run_scanline`)
- Test: `crates/machine/src/cps1.rs` (`mod tests`)

**Interfaces:**
- Produces: `impl Cps1 { pub fn step_instruction(&mut self) -> u32 }` — runs exactly one 68000 instruction, returns cycles consumed. Advances `total_cycles`, charges `carry`, and advances `line` (asserting vblank and latching objects) when the budget is exhausted.
- Consumes: nothing new.

⚠️ **This is the highest-risk task in the plan.** `run_scanline` is on the path every board-level test and the whole vector suite runs through. The refactor must be behaviour-preserving, and Step 2 exists to prove it before the refactor happens.

- [ ] **Step 1: Read the existing loop and write down its four responsibilities**

`crates/machine/src/cps1.rs:101-150`. Inside the `while budget > 0` loop: re-drive the IRQ level from `board.vblank_pending()`, step the CPU, decrement `budget`, accumulate `spent`. Outside it: the vblank/object-latch check at the top (keyed on `self.line == self.timing.vblank_line`), `carry = budget`, `total_cycles += spent`, `trace.sample_pc`, `line = (line + 1) % lines_per_frame`, and `trace.frames += 1` on wrap.

The design question this task turns on: **the per-line work is not per-instruction work.** `step_instruction` must do the per-instruction part every call and the per-line part only when a line actually ends.

- [ ] **Step 2: Write the divergence test first, against the *unrefactored* code**

This test must pass before the refactor and after it. That is the whole point: it pins current behaviour so the refactor cannot silently change it.

    ///
    /// A baseline, not a tautology: it passes trivially today, because `run_frame`
    /// *is* a loop over `run_scanline`. It is written before Task 1's refactor so
    /// that it is a pin rather than a fresh claim — if the refactor changes what a
    /// frame does, this fails, and it can only fail for that reason.
    #[test]
    fn a_frame_of_scanlines_equals_a_frame() {
        let mut a = a_running_machine();
        let mut b = a_running_machine();
        for _ in 0..a.timing.lines_per_frame {
            a.run_scanline();

        b.run_frame();
        assert_eq!(a.total_cycles, b.total_cycles);
        assert_eq!(a.line, b.line);
        assert_eq!(a.cpu.pc, b.cpu.pc);

- [ ] **Step 6: Extract `step_instruction` and rewrite `run_scanline` on top of it**

**No new field.** `Cps1::carry` already holds the mid-line state this needs, and it is
merely *scoped* wrongly for stepping: today the live budget is a local in
`run_scanline` and `carry` is only its value at a line end. Widen `carry` to be the
live budget — `cycles_per_line + previous carry` at a line start, counting down, `<= 0`
at a line end — and the two coincide exactly everywhere `carry` is currently
observed. That matters because `carry` is in [`MachineState`]: a save happens at a
frame boundary, where the budget is `<= 0`, so the saved value and its meaning are
unchanged and the format version does not move. A new `line_budget` field would have
had to answer that question; this way there is no question.

The shape. Note that the per-line work moves into `step_instruction`, guarded on the
budget having run out:

```rust
    /// Runs exactly one 68000 instruction, returning the cycles it consumed.
    ///
    /// The debugger's stepping primitive, and [`Cps1::run_scanline`] is a loop over
    /// it — **one code path deliberately.** A separate stepping path is a debugger
    /// that single-steps a machine subtly unlike the one that runs: the level-driven
    /// IRQ sync below is the specific thing that would be forgotten, and the symptom
    /// would be a machine that takes no interrupts under the debugger, which is the
    /// thing a debugger is most often opened to investigate.
    ///
    /// One instruction can overrun the scanline budget — a `divs` costs 158 cycles
    /// and does not divide at a line boundary — so this may end a line, in which
    /// case it does everything the end of a line does: sample the PC, advance the
    /// beam, count a frame on the wrap, and assert vblank and latch the object table
    /// on arriving at [`Timing::vblank_line`].
    pub fn step_instruction(&mut self) -> u32 {
        // The start-of-line work, done here rather than in `run_scanline` so a
        // caller that only ever steps still gets it. Guarded on the budget being
        // spent, so it happens once per line and not once per instruction.
        if self.carry <= 0 {
            self.carry += i64::from(self.timing.cycles_per_line);
            if self.line == self.timing.vblank_line {
                self.board.assert_vblank();
                self.video
                    .latch_objects(&self.board.gfxram[..], &self.board.cps_a);
            }
        }
        // Re-drive the level before **every** step. See the note in the git history
        // for `run_scanline`: the level is a level, nothing in the core clears it,
        // and the acknowledge happens on the far side of the bus.
        self.cpu
            .set_irq(if self.board.vblank_pending() { 2 } else { 0 });
        let c = self.cpu.step_with(&self.dec, &mut self.board);
        self.carry -= i64::from(c);
        self.total_cycles += u64::from(c);
        if self.carry <= 0 {
            self.board.trace.sample_pc(self.cpu.pc);
            self.line = (self.line + 1) % self.timing.lines_per_frame;
            if self.line == 0 {
                self.board.trace.frames += 1;
            }
        }
        c
    }

    /// Runs one scanline's worth of CPU, returning the cycles actually consumed.
    pub fn run_scanline(&mut self) -> u32 {
        let start = self.total_cycles;
        let line = self.line;
        while self.line == line {
            self.step_instruction();
        }
        u32::try_from(self.total_cycles - start).unwrap_or(u32::MAX)
    }
```

⚠️ **`carry`'s doc comment must be updated to say what it now holds**, since it changes from "the overshoot at a line end" to "the live budget, which at a line end is the overshoot". Keep the existing paragraph on why the overshoot is carried at all — that reasoning is unchanged and is the reason the field exists. Add that it is now also what makes stepping possible: a budget living in a local could not survive a return to the caller.

The first is the one that matters, and it is behavioural rather than structural: `&self` makes the mutation impossible to write, and this test is what makes the *requirement* explicit.

```rust
    /// Peeking never disturbs the machine.
    ///
    /// `read_word` calls `note_possible_ack`, which clears `vblank_pending` and
    /// bumps `trace.acks` on a read of the vector-26 longword, and records unmapped
    /// reads. A debugger's memory panel scrolled over $68 must not acknowledge the
    /// interrupt it was opened to investigate, and one parked on unmapped space must
    /// not fill the counter it displays with its own reads.
    ///
    /// Swept over the whole vector table *and* unmapped space, with an interrupt
    /// outstanding — the state in which every one of those side effects is live.
    #[test]
    fn peeking_does_not_disturb_the_machine() {
        let mut b = a_board();
        b.assert_vblank();
        assert!(b.vblank_pending(), "the premise: an interrupt is outstanding");
        let acks = b.trace.acks;
        let unmapped = b.trace.unmapped_reads.count();

        for addr in (0..0x400).step_by(2) {
            b.peek_word(addr);
        }
        for addr in (0x40_0000..0x40_0100).step_by(2) {
            b.peek_word(addr);
        }

        assert!(b.vblank_pending(), "the interrupt must still be outstanding");
        assert_eq!(b.trace.acks, acks, "no acknowledge was invented");
        assert_eq!(
            b.trace.unmapped_reads.count(),
            unmapped,
            "and the debugger's own reads are not in the counter"
        );

        // The control: the same read through `read_word` *does* disturb it, so this
        // test can tell a working `peek_word` from a machine that was never
        // disturbable in the first place.
        b.read_word(0x68);
        assert!(!b.vblank_pending(), "read_word acknowledges, which is why peek exists");
        assert_eq!(b.trace.acks, acks + 1);
    }

    /// Peek and read agree everywhere.
    ///
    /// Otherwise the debugger shows a different machine than the one running. Walked
    /// over one address from every range in the map plus both sides of every
    /// boundary, in a state where `read_word`'s side effects are inert — no
    /// interrupt pending — so the comparison is legal.
    #[test]
    fn peek_and_read_agree_across_the_address_map() {
        let mut b = a_board();
        assert!(!b.vblank_pending(), "the premise: no side effect is live");
        // Every boundary in `read_word`'s match, and one address either side.
        let edges = [
            0x00_0000u32, 0x3F_FFFE, 0x40_0000,
            0x7F_FFFE, 0x80_0000, 0x80_0006, 0x80_0008,
            0x80_0016, 0x80_0018, 0x80_001E, 0x80_0020, 0x80_0022,
            0x80_013E, 0x80_0140, 0x80_017E, 0x80_0180,
            0x8F_FFFE, 0x90_0000, 0x92_FFFE, 0x93_0000,
            0xFE_FFFE, 0xFF_0000, 0xFF_FFFE,
        ];
        for addr in edges {
            assert_eq!(
                b.peek_word(addr),
                b.read_word(addr),
                "peek and read disagree at {addr:#08X}"
            );
        }
        // A control: at least one of those addresses must decode and at least one
        // must not, or this loop is comparing None to None everywhere.
        assert!(b.peek_word(0xFF_0000).is_some(), "RAM decodes");
        assert!(b.peek_word(0x40_0000).is_none(), "and a gap does not");
    }

    /// Unmapped is `None`, not `0xFFFF`.
    ///
    /// "Nothing decodes here" and "this decodes and reads as all ones" are different
    /// facts, and a debugger that renders both as `FFFF` sends you looking in the
    /// wrong place. `0x800020` is the one address that genuinely reads `0xFFFF`
    /// while being decoded (MAME's `nopr`), which is what makes the distinction
    /// testable rather than theoretical.
    #[test]
    fn undecoded_and_all_ones_are_different_answers() {
        let b = a_board();
        assert_eq!(b.peek_word(0x40_0000), None, "a gap decodes nothing");
        assert_eq!(b.peek_word(0x80_0020), Some(0xFFFF), "nopr decodes to all ones");
    }
```

```rust

    /// effects.**
    ///
    /// For a debugger, a memory viewer, or anything else that reads the machine
    /// without being part of it. [`Board::read_word`] is what the CPU uses and it is
    /// not side-effect-free: it acknowledges a pending interrupt on a read of the
    /// vector-26 longword and records unmapped addresses in the trace. A viewer
    /// built on it would clear the interrupt it was opened to investigate.
    ///
    /// `&self` is the enforcement, not a preference: a `&mut self` version could
    /// call `note_possible_ack` and the compiler would not object.
    ///
    /// ⚠️ **This duplicates [`Board::read_word`]'s address map, and the two must
    /// agree.** `tests::peek_and_read_agree_across_the_address_map` is what holds
    /// them together; a change to either map goes in both places. Sharing the pure
    /// ranges is not possible without `&mut self` plumbing that would defeat the
    /// point, and the I/O ranges compute rather than store — the DIP-switch
    /// selector and the CPS-B self-test are both derivations, not fields.
    pub fn peek_word(&self, addr: u32) -> Option<u16> { /* the same match, no bookkeeping */ }
```

```rust

    ///
    /// See [`Board::peek_word`]: no side effects, which is why the debugger does not
    /// use the CPU's read path.
    pub fn peek_word(&self, addr: u32) -> Option<u16> {
        self.board.peek_word(addr)
    }
```
