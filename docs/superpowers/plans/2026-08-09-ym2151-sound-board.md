## The one thing measured before planning

The spec's central risk is that a *generated* suite can produce cases that cannot
fail. That was measured, and three findings changed the design before any code was
written. Two of them constrain tasks below and are repeated where they bind:

1. **A random register script is silent** — 0 of 500 cases produced a single
   non-zero sample. The script must be structured (Task 6).
2. **A held note never exercises release rate** — RR bit 0 was undetected in 0 of
   200 cases until every case keyed off at sample 256 of 512 (Task 6).
3. **Timer state is not audible at all** — 0 of 200 until the record gained a
   per-sample status byte (Task 5's format, Task 6's script).

And one finding constrains the core itself:

4. **The lazy `prepare()` gate is semantics, not an optimisation.** `prepare()`
   consumes the CSM key-on flag, so calling it every sample eats CSM triggers.
   Eager and lazy agree bit-for-bit with CSM off and diverge with CSM on
   (39,737 non-silent samples of 40,000 against 15,775). Task 9 implements the gate;
   Task 6 guarantees the suite contains CSM cases, without which no test can tell
   the two readings apart.

## Performance: sized before planning

D1's suite is 1,604,000 cases over 228 MB and runs in a few seconds. D2's is
**1,000 cases at 3,657 bytes each = 3.657 MB** — three orders of magnitude smaller.
Generation of 5,000 structured cases was measured at **1.5 s**.

So: no threads, no `rayon`, no `--quick` subset, no caching of generated files
beyond their presence on disk. Every case runs every time. If the suite exceeds
~10 s in release that is a real finding to report, not to work around.

```rust
#[cfg(test)]
mod tests {
    use super::*;

    /// The four tables, pinned by checksum rather than by proofreading.
    ///
    /// 768 hand-transcribed numbers cannot be verified by reading them. These
    /// figures were measured against ymfm's own tables on 2026-08-09 and are
    /// recorded in the spec; a table that is subtly wrong fails here rather than
    /// on one obscure note in one case of the suite.
    #[test]
    fn the_four_tables_match_their_measured_checksums() {
        assert_eq!(SIN.len(), 256);
        assert_eq!(SIN.iter().map(|&v| u32::from(v)).sum::<u32>(), 65_406);
        assert_eq!(fnv1a_u16(&SIN), 0x6901_6697_2613_166b);

        assert_eq!(POW.len(), 256);
        assert_eq!(POW.iter().map(|&v| u32::from(v)).sum::<u32>(), 115_543);
        assert_eq!(fnv1a_u16(&POW), 0xc284_cffe_0e13_3896);

        assert_eq!(PHASE_STEP.len(), 768);
        assert_eq!(PHASE_STEP.iter().map(u64::from).sum::<u64>(), 46_015_744);
        assert_eq!(PHASE_STEP[0], 41_568);
        assert_eq!(PHASE_STEP[767], 82_976);
        assert_eq!(fnv1a_u32(&PHASE_STEP), 0x3b0f_96a4_7792_bdb3);

        assert_eq!(INCREMENT.len(), 64);
        assert_eq!(INCREMENT.iter().map(u64::from).sum::<u64>(), 35_716_092_092);
        assert_eq!(fnv1a_u32(&INCREMENT), 0x7e8e_a956_6fb1_810d);
    }

    /// The phase-step table is chip data, not a formula — asserted, not assumed.
    ///
    /// ymfm's own comment says the computed table "differs in a few spots from the
    /// data verified from an actual chip". Measured: it diverges from a pure
    /// exponential by up to 106 units, its consecutive deltas are quantised to
    /// exactly {32, 64, 96, 128, 160}, and its span is 1.99615 rather than the
    /// formula's 1.99820. This test is why the table is transcribed rather than
    /// computed: a future reader who "simplifies" it into an exponential fails here.
    #[test]
    fn the_phase_step_table_is_not_an_exponential() {
        let mut deltas = std::collections::BTreeSet::new();
        for w in PHASE_STEP.windows(2) {
            deltas.insert(w[1] - w[0]);
        }
        assert_eq!(
            deltas.into_iter().collect::<Vec<_>>(),
            vec![32, 64, 96, 128, 160],
            "quantised chip data, not a smooth curve"
        );

        // The largest divergence from the best pure exponential through entry 0.
        let base = f64::from(PHASE_STEP[0]);
        let worst = PHASE_STEP
            .iter()
            .enumerate()
            .map(|(i, &g)| {
                let want = (base * 2f64.powf(i as f64 / 768.0)).round();
                (want - f64::from(g)).abs() as u32
            })
            .max()
            .unwrap();
        assert_eq!(worst, 106, "no formula reproduces this table");
    }

    /// The two computed tables are computed, and their formulas are exact.
    ///
    /// Both fits were measured at 0 of 256 mismatched. The near-misses are the
    /// reason this test exists: the obvious `2^(-i/256) * 2048` for the power table
    /// misses all 256 entries, and truncating instead of rounding misses 139. A
    /// `const fn` that is subtly wrong would otherwise be caught only by the
    /// checksum above, which does not say *why*.
    #[test]
    fn the_sine_and_power_tables_match_their_closed_forms() {
        for i in 0..256u32 {
            let want = (-(((f64::from(i) + 0.5) * std::f64::consts::PI / 512.0).sin())
                .log2()
                * 256.0)
                .round() as u16;
            assert_eq!(SIN[i as usize], want, "sine at {i}");
        }
        for i in 0..256u32 {
            let want = ((2f64.powf(-(f64::from(i) + 1.0) / 256.0) * 2048.0).round()
                - 1024.0) as u16;
            assert_eq!(POW[i as usize], want, "power at {i}");
        }
    }
}
```

- [ ] **Step 4: Write the tables**

In `crates/ym2151/src/tables.rs`, above the test module. The two computed tables use
`const`-evaluated loops if the toolchain allows floating point in `const fn` (it
does not, as of 1.93) — so they are `static` values built by a `LazyLock`-free
approach: compute them in a `const fn` using integer-only algorithms, or transcribe
them *with* the closed-form test above as the gate. Transcribing with a formula test
is acceptable and is the simpler path; the formula test is what makes it safe.

```rust
//! The OPM's four lookup tables, split by provenance.
//!
//! Two are exact closed forms and two are chip data, and treating them alike is how
//! a plausible wrong entry survives. Each is gated by a checksum measured against
//! ymfm on 2026-08-09, because 768 transcribed numbers cannot be proofread.
//!
//! - [`SIN`] and [`POW`] are formulas, verified at 0 of 256 mismatched each.
//! - [`PHASE_STEP`] is David Viens' analysis of real chip data
//!   (`ymfm_fm.ipp:206-320`), which ymfm's own comment notes "differs in a few
//!   spots" from the computed table. No formula reproduces it.
//! - [`INCREMENT`] is 64 packed-nibble values (`ymfm_fm.ipp:145`).

/// Sine as attenuation, 4.8 fixed point, first quarter period.
///
/// `round(-log2(sin((i + 0.5) * PI / 512)) * 256)`, which is exact — see the test.
pub static SIN: [u16; 256] = [
    // 0x859, 0x6c3, ... transcribe from ymfm_fm.ipp:50, gated by the formula test

/// Attenuation to 11-bit linear volume.
///
/// `round(2^(-(i + 1) / 256) * 2048) - 1024`. **The `i + 1` and the `- 1024` are
/// both load-bearing**: the obvious `2^(-i/256) * 2048` misses all 256 entries, and
/// truncating instead of rounding misses 139 of them.
pub static POW: [u16; 256] = [
    // 0x3fa, 0x3f5, ... transcribe from ymfm_fm.ipp:95, gated by the formula test
];

/// Phase step per key code, 12 notes x 64 key fractions.
///
/// **Chip data — do not replace with a formula.** See the module docs.
pub static PHASE_STEP: [u32; 768] = [
    // transcribe from ymfm_fm.ipp:230, gated by the checksum test
];

/// Envelope attenuation increments, four packed nibbles per rate.
pub static INCREMENT: [u32; 64] = [
    // transcribe from ymfm_fm.ipp:145, gated by the checksum test
];

/// FNV-1a over a `u16` table's little-endian bytes.
///
/// New to this repository — `grep` finds no existing FNV in `crates/` — so this is
/// the only implementation, and the generator's determinism check reuses it rather
/// than growing a second.
#[must_use]
pub fn fnv1a_u16(vals: &[u16]) -> u64 {
    let mut h: u64 = 0xcbf2_9ce4_8422_2325;
    for v in vals {
        for b in v.to_le_bytes() {
            h ^= u64::from(b);
            h = h.wrapping_mul(0x100_0000_01b3);
        }
    }
    h
}

/// FNV-1a over a `u32` table's little-endian bytes.
#[must_use]
pub fn fnv1a_u32(vals: &[u32]) -> u64 {
    let mut h: u64 = 0xcbf2_9ce4_8422_2325;
    for v in vals {
        for b in v.to_le_bytes() {
            h ^= u64::from(b);
            h = h.wrapping_mul(0x100_0000_01b3);
        }
    }
    h
}

/// The absolute sine attenuation for a 10-bit phase, with the sign in bit 15.
///
/// The table covers one quarter period; bit 8 mirrors it and bit 9 is the sign.
/// From `ymfm_fm.ipp:46`.
#[must_use]
pub fn abs_sin_attenuation(phase: u32) -> u16 {
    let index = phase & 0xFF;
    let folded = if phase & 0x100 != 0 { 0xFF - index } else { index };
    SIN[folded as usize] | (u16::from((phase >> 9) & 1) << 15)
}

/// A 5.8 attenuation converted to linear volume, with the implied leading 1.
///
/// From `ymfm_fm.ipp:86`: `POW[x & 0xFF] >> (x >> 8)`, and the `+ 1024` restores
/// the leading bit the table has factored out.
#[must_use]
pub fn attenuation_to_volume(atten: u32) -> u32 {
    (u32::from(POW[(atten & 0xFF) as usize]) + 1024) >> (atten >> 8)
}

/// A 4-bit increment for a 6-bit rate and a 3-bit counter position.
#[must_use]
pub fn attenuation_increment(rate: u32, index: u32) -> u32 {
    (INCREMENT[rate as usize] >> (4 * index)) & 0xF
}
```

**Careful with `attenuation_to_volume` and `abs_sin_attenuation`.** ymfm's `POW`
table stores the value *without* the implied leading 1 (entry 0 is 1018, not 2048),
and its `s_sin_table` already encodes the fold and sign. Read `ymfm_fm.ipp:46-133`
and reproduce exactly what it does, then check the two helpers against it with a
brute-force comparison in Task 7 rather than trusting this sketch — the `+ 1024`
and the fold above are the plan's reading and must be verified, not assumed.

```rust
//! The OPM register map and register file.
//!
//! # The one trap in this file
//!
//! A register address names an *operator index*, and that index is not the
//! operator's slot in the algorithm chain: indices 0, 1, 2, 3 are slots 1, 3, 2, 4.
//! Every test that writes all four of a channel's operators identically passes
//! under either map, so [`slot_of`] has its own test rather than relying on the
//! audio comparison to catch it.

/// The five per-operator register families, `0x40`-`0xFF`.
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum Family {
    /// `0x40`-`0x5F`: detune 1 and frequency multiple.
    Dt1Mul,
    /// `0x60`-`0x7F`: total level.
    Tl,
    /// `0x80`-`0x9F`: key scaling and attack rate.
    KsAr,
    /// `0xA0`-`0xBF`: AM sensitivity and first decay rate.
    AmsD1r,
    /// `0xC0`-`0xDF`: detune 2 and second decay rate.
    Dt2D2r,
    /// `0xE0`-`0xFF`: first decay level and release rate.
    D1lRr,
}

/// The OPM's 32 operators: 8 channels of 4.
pub const OPERATOR_COUNT: u32 = 32;

/// The slot in the algorithm chain for a register-operator index.
///
/// Slots are numbered 0-3 here, meaning chain positions 1-4. The mapping is a
/// two-bit swap: `0 -> 0, 1 -> 2, 2 -> 1, 3 -> 3`.
#[must_use]
pub const fn slot_of(op_index: u32) -> u32 {
    ((op_index & 1) << 1) | ((op_index >> 1) & 1)
}

/// Which family, channel, and register-operator index an address names.
///
/// `None` below `0x40`, where addresses are global rather than per-operator.
#[must_use]
pub fn decode(reg: u8) -> Option<(Family, u32, u32)> {
    if reg < 0x40 {
        return None;
    }
    let family = match reg >> 5 {
        2 => Family::Dt1Mul,
        3 => Family::Tl,
        4 => Family::KsAr,
        5 => Family::AmsD1r,
        6 => Family::Dt2D2r,
        _ => Family::D1lRr,
    };
    Some((family, u32::from(reg & 7), u32::from((reg >> 3) & 3)))
}

/// The OPM's 256-byte register file and the two depth registers behind `0x19`.
#[derive(Clone, PartialEq, Eq, Debug)]
pub struct Regs {
    /// Every written byte, by address.
    file: [u8; 0x100],
    /// `0x19` writes here when bit 7 is clear.
    am_depth: u8,
    /// `0x19` writes here when bit 7 is set. **Not** a register `0x1A` — ymfm's
    /// `1A` is an internal fake and is not an OPM address.
    pm_depth: u8,
}
```

Every accessor is a bitfield read of `file`. Write them from `ymfm_opm.h:47-101`
and give each one a doc comment naming its register and bit range. `write` stores
into `file`, with `0x19` routed to `am_depth` or `pm_depth` by bit 7.

`ch_block_freq(ch)` assembles `0x28`'s 7 bits and `0x30`'s 6 into the 13-bit
`BBBCCCCFFFFFF` layout `cache_operator_data` expects: `(kc << 6) | (kf >> 2)`.
Check that shift against `ymfm_opm.cpp`'s `ch_block_freq` — the plan's reading is
that `0x30`'s low 2 bits are unused, which is what made the spec's first sensitivity
measurement report a false 0%.

- [ ] **Step 3: Implement the operator**

Port `fm_operator::clock_envelope`, `start_attack`, `start_release`,
`clock_keystate`, `envelope_attenuation`, `compute_volume`, and `clock_phase` from

```rust
/// Advances the envelope, if this counter value is an envelope tick for its rate.
///
/// `env_counter` is the engine's counter already divided by 4. The rate's top four
/// bits are a shift: a rate of 4n ticks every 2^(11-n) counts, which is how one
/// counter drives rates spanning four orders of magnitude.
pub fn clock_envelope(&mut self, env_counter: u32, cache: &OpCache) {
    if self.env_state == EnvState::Attack && self.env_attenuation == 0 {
        self.env_state = EnvState::Decay;
    }
    // Immediately after, in the same clock: a D1L of 0 means decay has nothing to
    // do and sustain starts now.
    if self.env_state == EnvState::Decay && self.env_attenuation >= cache.eg_sustain {
        self.env_state = EnvState::Sustain;
    }

    let rate = u32::from(cache.eg_rate[self.env_state as usize]);
    let rate_shift = rate >> 2;
    let counter = env_counter << rate_shift;
    if counter & 0x7FF != 0 {
        return;
    }
    let pick = if rate_shift <= 11 { 11 } else { rate_shift };
    let increment = tables::attenuation_increment(rate, (counter >> pick) & 7);

    if self.env_state == EnvState::Attack {
        // Rates 62 and 63 are the documented glitch: they do not increment once
        // keyed on, having been snapped to 0 by `start_attack`.
        if rate < 62 {
            let a = u32::from(self.env_attenuation);
            self.env_attenuation = (a + (((!a) * increment) >> 4)) as u16;
        }
    } else {
        self.env_attenuation += increment as u16;
        if self.env_attenuation >= 0x400 {
            self.env_attenuation = 0x3FF;
        }
    }
}
```

**Check the attack formula's width.** ymfm uses `(~m_env_attenuation * increment)
>> 4` on a `uint32_t` holding a 10-bit value, so `~` sets the top 22 bits and the
result relies on the truncation back into 10 bits. Reproduce the *arithmetic*, not
the literal `!` on a `u16`: mask to 10 bits explicitly and assert the invariant
`env_attenuation <= 0x3FF` in a debug assertion. Getting this wrong makes attacks
subtly the wrong shape, which the suite catches but the unit tests above do not.

    use crate::regs::Regs;

    /// An octave up doubles the phase step, exactly.
    ///
    /// The block field is a shift, so this must hold to the bit even though the
    /// underlying table is not an exponential. A core that folded the block into
    /// the table lookup instead of shifting after it fails here.

    fn each_octave_doubles_the_phase_step() {
        let mut r = Regs::new();
        r.write(0x40, 0x01); // MUL = 1, DT1 = 0
        let mut steps = [0u32; 7];
        for (block, slot) in (0..7u8).zip(steps.iter_mut()) {
            r.write(0x28, block << 4); // note 0 of each octave
            *slot = OpCache::compute(&r, 0, 0, 0).phase_step;
        }
        for w in steps.windows(2) {
            assert_eq!(w[1], w[0] * 2, "octave doubling: {steps:?}");
        }
    }

    /// The frequency multiple scales the step, and MUL = 0 means one half.
    ///
    /// The register field is 4 bits, 0-15, and the multiplier is `2 * mul` except
    /// that 0 means 1 — i.e. the step is `base * mul` with `mul = 0` behaving as
    /// `0.5`. A core that treated 0 as 0 would make every operator with MUL = 0
    /// silent, which is a common patch setting.

        let mut r = Regs::new();
        r.write(0x28, 0x40);
        r.write(0x40, 0x00);
        let half = OpCache::compute(&r, 0, 0, 0).phase_step;
        r.write(0x40, 0x01);
        let one = OpCache::compute(&r, 0, 0, 0).phase_step;
        r.write(0x40, 0x02);
        let two = OpCache::compute(&r, 0, 0, 0).phase_step;
        assert!(half > 0, "MUL=0 is audible");
        assert_eq!(one, half * 2);
        assert_eq!(two, one * 2);

    /// DT2 shifts by a fixed amount per setting, and 0 is no shift.
    ///
    /// DT2 adds to the key code before the table lookup: 0, +384, +500, +608 in
    /// units of 1/768 octave (`ymfm_opm.cpp`'s `s_detune2_delta`). Values are
    /// asserted as ratios rather than raw steps so the test does not depend on the

            let s = OpCache::compute(&r, 0, 0, 0).phase_step;
            assert!(s > *seen.last().unwrap(), "DT2 {dt2} raises the pitch");
            seen.push(s);

        let ratio = f64::from(seen[3]) / f64::from(base);
        assert!(

            "DT2=3 is 608/768 of an octave, got {ratio}"

    ///
    /// The DT1 table is chip data indexed by `key_code >> 2` and the detune
    /// magnitude, with bit 2 of the register as the sign. Settings 0 and 4 are both
    /// zero magnitude, so they must produce the identical step — a core that read
    /// the sign bit as part of the magnitude would make setting 4 a detune.
    #[test]
    fn detune_one_settings_zero_and_four_are_both_no_ops() {
        let mut r = Regs::new();
        r.write(0x28, 0x4A);
        r.write(0x40, 0x01);
        r.write(0x40, 0x01 | (0 << 4));
        let zero = OpCache::compute(&r, 0, 0, 0).phase_step;
        r.write(0x40, 0x01 | (4 << 4));
        let four = OpCache::compute(&r, 0, 0, 0).phase_step;
        assert_eq!(zero, four, "magnitude 0 with the sign set is still 0");

        // And a real detune moves in both directions by the same magnitude.
        r.write(0x40, 0x01 | (2 << 4));
        let up = OpCache::compute(&r, 0, 0, 0).phase_step;
        r.write(0x40, 0x01 | (6 << 4));
        let down = OpCache::compute(&r, 0, 0, 0).phase_step;
        assert!(up > zero, "DT1 = 2 detunes up");
        assert!(down < zero, "DT1 = 6 is the same magnitude down");
        assert_eq!(up - zero, zero - down, "symmetric about the base");

    ///
    /// A constant offset would be a transpose. This test measures the same DT1
    /// setting at two key codes an octave apart and asserts the offsets differ,
    /// which is the property that distinguishes the real table from any constant.
    #[test]
    fn detune_one_scales_with_the_key_code() {
        let mut r = Regs::new();

            r.write(0x28, kc);
            r.write(0x40, 0x01);
            let base = OpCache::compute(&r, 0, 0, 0).phase_step;
            r.write(0x40, 0x01 | (3 << 4));
            deltas.push(OpCache::compute(&r, 0, 0, 0).phase_step - base);
        }
        assert_ne!(deltas[0], deltas[1], "a detune, not a transpose: {deltas:?}");

            let mut lfo = Lfo::new();
            let mut pm = vec![];
            for _ in 0..2048 {
                pm.push(lfo.clock(&r).1);
            }
            shapes.push(pm);
        }

            let mut s: Vec<i32> = v.clone();
            s.sort_unstable();
            s.dedup();
            s.len()

mod tests {
    use super::*;

    /// The LFSR is 17 bits and its period is 2^17 - 1.
    ///
    /// Measured by running it until the state repeats, not by asserting a number
    /// taken from the implementation. A 16-bit or 18-bit tap set gives a different
    /// period, and a broken tap gives a short one — all three fail here.
    #[test]
    fn the_lfsr_period_is_one_hundred_thirty_one_thousand_and_seventy_one() {
        let mut n = Noise::new();
        let start = n.state();
        let mut steps = 0u32;
        loop {
            // Frequency 0 is the fastest: one shift per clock.
            n.clock(0);
            steps += 1;
            if n.state() == start || steps > 200_000 {
                break;
            }
        }
        assert_eq!(steps, 131_071, "2^17 - 1");
    }

    /// The LFSR never reaches all-zero, which would lock it up.
    #[test]
    fn the_lfsr_never_locks_at_zero() {
        let mut n = Noise::new();
        for _ in 0..200_000 {
            n.clock(0);
            assert_ne!(n.state(), 0, "an all-zero LFSR never shifts again");
        }
    }

    /// The frequency field divides the shift rate, and 31 is the slowest.
    ///
    /// `NFRQ` counts down from `32 - freq`, so a higher value shifts *more* often.
    /// Measured by counting shifts over a fixed window rather than by reading the
    /// divider out of the implementation.
    #[test]
    fn the_frequency_field_divides_the_shift_rate() {
        let mut counts = vec![];
        for freq in [0u32, 16, 31] {
            let mut n = Noise::new();
            let mut prev = n.state();
            let mut shifts = 0;
            for _ in 0..4096 {
                n.clock(freq);
                if n.state() != prev {
                    shifts += 1;
                    prev = n.state();
                }
            }
            counts.push(shifts);
        }
        assert!(
            counts[0] < counts[1] && counts[1] < counts[2],
            "higher NFRQ shifts more often: {counts:?}"
        );
    }

`OpCache::compute` ports `cache_operator_data` and `compute_phase_step` from

mod tests {

    /// A helper: set up one channel with a given algorithm, all four operators
    /// audible, and one operator silenced by total level.
    fn peak_with_one_silenced(algorithm: u8, silenced: Option<u8>) -> i32 {
        let mut chip = crate::Ym2151::new();
        chip.write(0x20, 0xC0 | algorithm); // channel 0: both pans, ALG
        for op in 0..4u8 {
            let off = op * 8;
            chip.write(0x40 + off, 0x01); // MUL = 1
            chip.write(0x60 + off, if Some(off) == silenced { 127 } else { 0 });
            chip.write(0x80 + off, 31); // AR = 31, fastest
            chip.write(0xA0 + off, 0);  // D1R = 0, hold
            chip.write(0xC0 + off, 0);
            chip.write(0xE0 + off, 0);  // D1L = 0, RR = 0
        }
        chip.write(0x28, 0x4A);
        chip.write(0x08, 0x78); // key on all four slots of channel 0
        let mut buf = [(0i16, 0i16); 512];
        chip.generate(&mut buf);
        buf.iter().map(|&(l, _)| i32::from(l).abs()).max().unwrap()

- [ ] **Step 5: Implement channels, timers, and the chip**

`ALGORITHM_OPS` transcribes `s_algorithm_ops` from `ymfm_fm.ipp`'s `output_4op`,
including the `opout[8]` indirection: each entry names which of the eight scratch
slots feeds each operator's modulation input and which slots sum into the output.
Port `output_4op` structurally rather than special-casing eight algorithms by hand.

`Ym2151::generate` per sample, in this order (from `fm_engine_base::clock` and
`ym2151::generate`):

1. `clock_noise_and_lfo` — advance the LFO and the noise LFSR.
2. Clock the timers; on a timer A overflow with CSM set, set the CSM key-on for
   every channel and mark them modified.
3. `prepare()` if modified or if the 4,096-sample counter wrapped — **Task 9**
   implements the gate; for now call it every sample and leave a `TODO(task-9)`
   with the divergence figures in the comment so a reader does not "fix" it early.
4. Every 3rd sample (`EG_CLOCK_DIVIDER = 3`), advance the envelope counter and clock
   every operator's envelope.
5. Clock every operator's phase.
6. Sum all eight channels into left and right, clamp to `i16`.
7. Apply the YM3012 DAC roundtrip (`roundtrip_fp`): a 10-bit mantissa with a 3-bit
   exponent, which quantises quiet samples. **This is not optional** — it is why
   the reference's output fits `i16`, and skipping it makes every quiet sample
   differ from the suite.

**Do not sum only the active channels.** The spec measured `chanmask &=
m_active_channels` as a pure optimisation: deleting it changed no sample over 40,000,
CSM on or off. Summing all eight unconditionally is simpler and provably identical.

`crates/testrunner/src/ymgen.cpp` — a single translation unit that `#include`s

requirements that shape the register script:

```cpp
// Generates the AYMV vector file from ymfm, the implementation MAME uses.
//
// This file is BUILT against ymfm; no ymfm source is vendored in this repository.
// `crates/testrunner/src/ymfm.rs` fetches the archive, verifies it, and invokes c++.
//
// THE REGISTER SCRIPT IS STRUCTURED, NOT RANDOM. Three measurements forced this:
//   * A purely random script is silent: 0 of 500 cases produced one non-zero
//     sample. Every case must set up a playable patch and key on.
//   * A held note never exercises release rate: RR bit 0 was undetected in 0 of
//     200 cases until every case keys OFF at sample 256 of 512.
//   * Timer state is not audible: undetected in 0 of 200 until the record gained
//     a per-sample status byte.
//
// AND: CSM. The lazy prepare() gate consumes the CSM key-on flag, so a Rust port
// that prepares eagerly is wrong ONLY in CSM mode. Cases where `seed % 8 == 0`
// enable 0x14 bit 7 with timer A running, and the host below FIRES the timers.
// Without a firing host the whole comparison is vacuous — measured: CSM-on and
// CSM-off hashes came out identical until engine_timer_expired was actually
// called.

struct Host : public ymfm::ymfm_interface {
    int64_t deadline[2] = {-1, -1};
    int64_t now = 0;
    bool irq = false;

    void ymfm_set_timer(uint32_t tnum, int32_t duration) override {
        deadline[tnum] = (duration < 0) ? -1 : now + duration;
    }
    void ymfm_update_irq(bool asserted) override { irq = asserted; }

    // Advances `clocks` input clocks, firing each timer that comes due inside the
    // window in chronological order. THIS is what makes CSM cases meaningful.
    void advance(int64_t clocks) {
        int64_t end = now + clocks;
        for (;;) {
            int best = -1;
            for (int t = 0; t < 2; t++)
                if (deadline[t] >= 0 && deadline[t] <= end
                    && (best < 0 || deadline[t] < deadline[best]))
                    best = t;
            if (best < 0) break;
            now = deadline[best];
            deadline[best] = -1;
            m_engine->engine_timer_expired(best);
        }
        now = end;
    }
};
```

The script per case, driven by a xorshift64 seeded from the case index so the whole
file is reproducible from an integer:

1. Pick an algorithm (`seed % 8`), a feedback level, a key code and key fraction.
2. Write all four operators with rates drawn so that AR is fast enough to be audible
   within 256 samples and RR is non-zero — the measured requirements.
3. Enable both pans on at least one channel, and give the case 1-3 channels.
4. `seed % 8 == 0`: set `0x14` bit 7 (CSM) plus timer A load and enable, with a
   period that fires several times inside 512 samples.
5. `seed % 5 == 0`: enable the LFO with a non-zero depth; `seed % 7 == 0`: enable
   noise on channel 7.
6. Key on at sample 0. **Key off at sample 256, unconditionally.**
7. Record 512 samples, each as left, right, and the status byte read through the
   chip's own `read_status()`.

Total writes per case land near 272, which is where `CASE_BYTES(272, 512)` comes
from. The generator asserts its own write count fits `u16`.

    /// The Z80's clock does not divide evenly into a scanline.
    ///
    /// **This is the first inexact division in this project.** The 68000's 10 MHz
    /// over 15,625 lines/s is exactly 640 T/line and the pixel clock is exactly 512
    /// per line — both asserted above. The sound Z80 runs at XTAL(3'579'545), and
    /// 3,579,545 / 15,625 = 229.09088 T/line, which is 715,909/3,125.
    ///
    /// Truncating to 229 loses 1,420 T per second — 396.7 ppm, about 71 ms of drift
    /// across a three-minute match. So the scheduler carries a rational accumulator
    /// instead, and this test pins the remainder that makes it necessary.
    #[test]
    fn the_z80_clock_does_not_divide_into_a_scanline() {
        assert_eq!(Z80_HZ, 3_579_545);
        assert_eq!(SOUND_XTAL, 3_579_545);
        let lines_per_second = PIXEL_CLOCK / HTOTAL; // 15,625
        assert_eq!(lines_per_second, 15_625);
        assert_eq!(
            Z80_HZ % lines_per_second,
            1_420,
            "the remainder that forbids a truncated constant"
        );
        assert_eq!(Z80_HZ / lines_per_second, 229, "and the truncated value");
        assert_eq!((Z80_T_NUM, Z80_T_DEN), (715_909, 3_125));
        // 3,125 is 5^5, so the accumulator is exact after 3,125 lines and never
        // accumulates floating-point error — there is no float here at all.
        assert_eq!(5u32.pow(5), 3_125);
    }

    /// The accumulator is exact over its period: 3,125 lines is exactly 715,909 T.
    ///
    /// The property that makes this correct rather than merely better than
    /// truncating. A truncated 229 gives 715,625 over the same span — 284 short.
    #[test]
    fn the_rational_accumulator_is_exact_over_its_period() {
        let mut acc = RationalAccumulator::new(Z80_T_NUM, Z80_T_DEN);
        let total: u64 = (0..Z80_T_DEN).map(|_| u64::from(acc.advance())).sum();
        assert_eq!(total, u64::from(Z80_T_NUM), "exact after one period");
        assert_eq!(acc.remainder(), 0, "and back where it started");
        assert_eq!(229u64 * u64::from(Z80_T_DEN), 715_625, "what truncating costs");
    }

    /// Each line gets 229 or 230 T-states, never anything else.
    ///
    /// A scheduler that handed out a burst to catch up would put the Z80's writes in
    /// the wrong scanline. The accumulator spreads the remainder one T at a time.
    #[test]
    fn each_line_gets_two_hundred_twenty_nine_or_thirty() {
        let mut acc = RationalAccumulator::new(Z80_T_NUM, Z80_T_DEN);
        let mut counts = std::collections::BTreeMap::new();
        for _ in 0..Z80_T_DEN * 3 {
            *counts.entry(acc.advance()).or_insert(0u32) += 1;
        }
        assert_eq!(counts.keys().copied().collect::<Vec<_>>(), vec![229, 230]);
        // 1,420 of every 3,125 lines get the extra T.
        assert_eq!(counts[&230], 1_420 * 3);
        assert_eq!(counts[&229], (3_125 - 1_420) * 3);
    }

    /// A frame is 60,021.81056 T, and the accumulator does not round it away.
    ///
    /// 262 lines at 715,909/3,125 each. The fractional part is why a per-frame
    /// integer constant is also wrong, not just a per-line one.
    #[test]
    fn a_frame_is_not_a_whole_number_of_t_states_either() {

        let frame: u32 = (0..VTOTAL).map(|_| acc.advance()).sum();
        // The first frame gets 60,021 or 60,022 depending on the phase; over 3,125
        // lines the average is exact, which the period test above proves.
        assert!(frame == 60_021 || frame == 60_022, "got {frame}");
        assert_ne!(acc.remainder(), 0, "a frame is not a whole period");

/// The sound board's crystal, `XTAL(3'579'545)` — the NTSC colour subcarrier.
///
/// Both the Z80 and the YM2151 run from it, which is why one accumulator can drive
/// both. From `cps1.cpp`'s `MCFG_CPU_ADD("audiocpu", Z80, XTAL_3_579545MHz)`.
pub const SOUND_XTAL: u32 = 3_579_545;

/// The sound Z80's clock, in Hz. Same crystal, undivided.
pub const Z80_HZ: u32 = SOUND_XTAL;

/// T-states per scanline, as an exact fraction: 715,909 / 3,125.
///
/// **The first inexact division in this project.** See
/// [`the_z80_clock_does_not_divide_into_a_scanline`]. The denominator is 5^5, so a
/// `u32` accumulator is exact and never needs a float.
pub const Z80_T_NUM: u32 = 715_909;
/// The denominator of [`Z80_T_NUM`]. 3,125 = 5^5.
pub const Z80_T_DEN: u32 = 3_125;

/// Input clocks per YM2151 sample. Exactly 64: the chip divides by 2 then by 32.
pub const YM_SAMPLE_CLOCKS: u32 = 64;

/// Hands out `num / den` units per step without drifting.
///
/// Integer only: the remainder carries between steps, so the total after `den` steps
/// is exactly `num`. Used for the Z80's T-states per line and the YM2151's samples
/// per T-state, both of which are fractional.
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct RationalAccumulator {
    num: u32,
    den: u32,
    rem: u32,
}

impl RationalAccumulator {
    /// A new accumulator at zero remainder.
    ///
    /// # Panics
    ///
    /// If `den` is zero. This is an internal invariant, not guest input.
    #[must_use]
    pub const fn new(num: u32, den: u32) -> Self {
        assert!(den != 0, "a zero denominator is a programming error");
        Self { num, den, rem: 0 }
    }

    /// The whole units for this step, carrying the fraction forward.
    pub fn advance(&mut self) -> u32 {
        let total = self.num + self.rem;
        self.rem = total % self.den;
        total / self.den
    }

    /// The carried fraction, in units of `1 / den`.
    #[must_use]
    pub const fn remainder(&self) -> u32 {
        self.rem
    }
}

- [ ] **Step 3: Wire the Z80 into `step_instruction`**

The existing start-of-line block in `cps1.rs` is guarded on `self.carry <= 0`. The

```rust

            self.carry += i64::from(self.timing.cycles_per_line);
            // The Z80's line is 229 or 230 T-states — 715,909/3,125, the first
            // inexact division in this project. `z80_debt` carries the overshoot
            // from an instruction that ran past the line boundary.

            self.line += 1;
            // ... existing vblank and object-latch handling, unchanged
        }
```

and after the 68000's step:

```rust
        // The 68000 first, then the Z80: MAME's interleave order. Running the Z80
        // first gives it a one-line-stale command latch.
        while self.z80_debt > 0 {
            self.sound.set_latch(0, self.board.sound_command());
            self.sound.set_latch(1, self.board.sound_fade());
            let t = self.z80.step(&mut self.sound);
            self.z80_debt -= i64::from(t);
            self.z80_total = self.z80_total.wrapping_add(u64::from(t));
            // The YM2151 runs from the same crystal: one sample per 64 T-states,
            // accumulated over T-states actually spent rather than over lines, so
            // it stays locked to the Z80.
            self.sample_acc += t;
            while self.sample_acc >= timing::YM_SAMPLE_CLOCKS {
                self.sample_acc -= timing::YM_SAMPLE_CLOCKS;
                let mut one = [(0i16, 0i16); 1];
                self.sound.ym().generate(&mut one);
                self.samples.push(one[0]);
            }
            self.z80.set_irq(if self.sound.ym_irq() { 1 } else { 0 });
        }
```

    ///
    /// **This is what makes the debugger's machine the same machine.** A stepping
    /// path that skipped the sample accumulator would let a user step through the
    /// sound driver and hear nothing, then wonder which of the two was lying. Run
    /// one machine by scanline and step another instruction-by-instruction over the
    /// same T-state span; the samples must match exactly.
    #[test]
    fn stepping_and_running_produce_the_same_samples() {
        let mut running = Cps1::new_for_test();

            stepping.step_sound_instruction();

        // prefix they both cover rather than the whole buffer.

  and the test gained the assertion tying the array's length to the window.
- **Two controls had stopped being controls, in the two different ways Step 5
  names.** `ymsched`'s first, dropping `Copy` from `SoundTrace`, scored NO-BUILD —
  it breaks `pub const fn trace(&self) -> SoundTrace`, so nothing was measured;
  dropping `Debug` instead would not compile either, because `SoundBoard`'s
  hand-written impl formats `trace`, so the target became that formatter reporting a
  constant bank. And `font`'s `CONTROL-line-height-unused-until-task-4`, honest when
  written, is now genuinely killed by
  `all_five_panels_can_be_shown_at_once_without_overlapping` — Task 12's sound panel
  claimed the layout `LINE` feeds. Replaced with a pixel added to `~`, the one
  printable character no panel draws, verified distinct from all 94 others and
  outside the sixteen hex digits the literals pin. **This is the argument for
  `--all` rather than one set:** a later task can silently turn another set's control
  into a real mutant, and only the roll-up sees it.
- **A tracked `.pyc` had to be untracked first.** `scripts/__pycache__` was in the
  index, so every harness run dirtied the tree and Step 4's "`git status` must be
  empty" check could not have meant anything.

Final: 210/210 as expected across every set (207 on the first run, then 43/43 on the
three re-run sets). Tree verified clean after both runs — no mutant stranded.

## Definition of Done

Copied from the spec, plus the two regression gates:

1. `crates/ym2151` builds with no runtime dependencies and is `no_std`-compatible.
   **Verified by building, not by reading the `cfg_attr`:**
   `rustup target add thumbv7em-none-eabihf` then
   `cargo build -p ym2151 --no-default-features --target thumbv7em-none-eabihf`.
   `m68k` and `z80` pass the same command; `video` does not and is not claimed to —
   it allocates a framebuffer, so it is `alloc`-shaped. Worth adding to a future
   sub-project's gate: the `cfg_attr` alone compiles happily while a `std::` path
   creeps into production code, because the workspace default builds with `std` on.
2. The four tables match their measured checksums, with the two computed ones also
   asserted against their closed forms.
3. The YM2151 suite at **1,000/1,000 cases**, sample-exact on both channels and on
   the status trace.
4. The suite's own discriminating power asserted: the cases non-silent, plus the
   IRQ-edge and status-variation premises, plus the runner's corruption test.
   (**"100% non-silent" as first written is not achievable on correct data** —
   measured 993/1,000, the other seven sitting under the DAC's quantisation because
   their total level is near the generator's cap with a slow decay. The threshold is
   95%, and the premise it guards is measured at 0/500 for a random script, so the
   failure mode is two orders of magnitude away from the tolerance.)
5. **A CSM case in the suite** — at least 100 cases enabling `0x14` bit 7 with timer
   A running and a host that fires it. Without this the lazy-`prepare()` divergence
   is invisible and an eager port passes at 1,000/1,000 while being wrong.
6. The sound board's whole map covered, including the 2-bank window, the counted OKI
   stub, and the counted absent I/O ports.
7. The Z80's inexact clock carried as a rational accumulator, its remainder part of
   the save state, and the inexactness asserted beside `timing.rs`'s exactness
   assertions.
8. A save state round-trips the whole sound board and the two copies stay in step for
   2,000 further scanlines.
9. `step_sound_instruction` shares one code path with the scheduler, proven by a
   stepped machine's samples matching a run machine's over the same T-state span,
   and the overlay's sound panel renders without panicking.
10. **SF2's sound program runs** with a user-supplied ROM set: the Z80 executes from
    `audiocpu`, reads the command latch, writes YM2151 registers, and the chip
    produces non-silent samples — asserted as trace counters over 120 frames, in the
    one test permitted to skip loudly when the ROM is absent.
11. The mutation pass green, with the eager-`prepare()`-plus-no-CSM control surviving
    the suite and dying to the unit test.
12. **The Z80 vector suite still at 1,604/1,604 files, 1,604,000/1,604,000 cases, and
    the 68000 suite still at 127/127, 317,500/317,500.**
13. No sound is produced. No ROM is downloaded, bundled, or committed. `testdata/` is
    absent from `git status`.

## What D2 does not do

D3's scope, listed here so nobody implements it early: the OKI MSM6295's ADPCM
decoding, the host audio device, the mono mix CPS-1 actually sends to the cabinet
speaker, resampling to the host's rate, and the buffer-underrun policy. `0xF002` and
`0xF006` are counted stubs precisely so D3 has evidence about how the driver uses
them.
